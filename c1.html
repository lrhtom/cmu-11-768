智能体是什么，它怎么用工具

智能体（agent）说穿了，就是一个语言模型在循环里反复调用工具。第 1 讲先把这件事讲清楚。智能体和环境之间交换什么，模型和外壳（harness）各管什么。好智能体需要哪六种能力。这些能力靠训练模型，还是靠打磨外壳来获得。最后看一个智能体系统由哪几块软件组成。第 2 讲专讲最基础的能力：工具调用。工具怎么描述，调用怎么变成 token，外壳怎么解析和分发。怎么保证格式不出错，REST API 和 MCP 两种接法。最后是并行调用和评测。

智能体是什么、怎么工作

智能体就是语言模型加一个外壳。模型只管读 token、写 token。外壳把工具说明和工具结果变成 token 喂给模型。模型写出工具调用，外壳解析出来，拿到环境里执行。这样一圈一圈地转，直到任务完成。好用的智能体要六种能力。比如准确调工具，长上下文里不忘事。每种能力都能靠训练模型或打磨外壳得到。真跑起来的智能体是一整套系统。外壳、沙箱、推理服务、训练框架、监控，缺一不可。

4. 智能体就是能感知环境、又能作用于环境的东西

凡是能感知环境、又能作用于环境的东西，都是智能体 15:10。这是课上引用的经典 AI 教科书的定义。感知靠传感器，作用靠执行器。这个定义放到今天的 LLM 智能体上依然成立。以前的智能体技术，比如搜索和强化学习，大多还用得上 15:54。

5. 工具调用就是三条消息：定义、调用、结果

模型自己不会动手。外壳先告诉它有哪些工具。它写出调用，外壳去执行，再把结果按 ID 送回去。

先复习语言模型。它每一步预测下一个 token 的分布，采样一个接到后面，再重复 18:05。思维链（chain of thought）就是先写一串中间推理当草稿纸，再给答案。比如讲义第 10 页的 2 × (3 + 4) → 推理 → 14 18:51。到这里模型还只是在回应提示，不会"动手"。

让模型动手的主要办法是工具。工具放在环境里，给模型一个和环境交互的接口。比如把天气网站的 API 包一层，模型就能查天气 19:34。一个工具要告诉模型三件事。名字、一句话描述、参数的结构 20:18。参数结构用 JSON Schema 写。这份定义经过聊天模板渲染成文本，再切成 token 喂给模型。模型要么训练过，要么看几个例子，就知道怎么用这些工具 21:01。

{
  "name": "read_file",
  "description": "Read a UTF-8 file.",
  "parameters": {
    "type": "object",
    "properties": { "path": { "type": "string" } },
    "required": ["path"]
  }
}

模型要用工具，就生成一个工具调用。调用里写函数名和参数，这里是 JSON 21:47。外壳执行后，把结果放进一条 role: tool 的消息。消息里用 tool_call_id 指明它回应的是哪次调用。再经模板渲染成 token，让模型接着读 22:29。

6. 智能体就是把模型放进一个循环里转

外壳每转一圈，就把全部历史喂给模型一次 23:12。模型写调用，外壳执行，结果接回历史。两边的分工是这样的：

语言模型

只管 token 进、token 出。多模态模型也只是多了图片 token。工具调用对它来说，只是另一种能预测的 token 序列。序列里写明调哪个工具、给什么参数（讲义第 13 页）。

外壳（harness）

把语言模型当引擎，负责协调工具调用。它解析、校验、执行模型写出的调用。再把结果变成"观察"token 送回去 23:56。什么时候停，也由外壳决定。

Toolformer 当年说明：可以训练模型去调工具 23:56。返回的结果还能让后面的文本更准。有了这个基础，智能体就是跑一个循环。影响很大的一种做法叫 ReAct（reasoning + acting）：先写推理，再做动作 23:56。每一步模型读到的东西有四块 24:39：

  1. 上下文这类任务的总体说明，比如"解决 GitHub 上的 issue"
  2. 任务用户这一次的具体请求
  3. 工具清单用上一节那种格式写的全部可用工具
  4. 历史之前所有的动作和观察

模型读完这四块，先写一段推理，再给出一个或多个工具调用。调用在环境里执行，结果追加进历史，环境也跟着变。然后再来一轮 25:24。

怎么结束？可以给一个专门的"结束"工具，比如给用户发消息（讲义第 14 页的 send_message）。调用它就表示做完了。也可以干脆不再调用工具。智能体怎么判断自己做完了，规划那一讲再细说 26:08。

代码层面非常简单。讲义第 15 页摘了 mini-swe-agent 的核心 26:50。它很小，在编程智能体最常用的基准 SWE-bench 上分数却很高。讲师推荐去读它的源码。它先放进系统消息和用户消息，然后无限循环 27:33。每圈四步。先用全部历史查询模型，再把回复加进历史。然后执行回复里的动作，把观察加进历史。

    self.messages = []
    self.add_messages(

        self.model.format_message(role="user", content=self._render_template(self.config.instance_template)),
    )
    while True:
        self.step()

8. 好用的智能体要六种能力，安全也算一种

做一个智能体不难，难的是做一个真正好用的。下半节由 Graham 讲。现在有现成的库调模型推理，搭个能跑的很容易 30:36。

他先让大家说，用智能体时最烦什么 31:19。大家的抱怨是：太慢、啰嗦、会忘事、忘了上次会话。还有误解你的意思然后做错，访问不该访问的东西。常识上有奇怪的盲区，两行能解决的事写一千行。你提了不合理的要求，它也不反驳。它会说谎，还暗含很多假设 32:06。他归纳成六种能力（讲义第 17 页）：

9. 问题通常先在外壳里补上，再被训进模型

每种能力都有两种获得方式：训练模型，或者打磨外壳（讲义第 18 页）35:06。

训练 LLM（LLM training）

通过预训练、监督微调（SFT）或强化学习（RL）改变模型行为。教会它推理、用工具、出错后恢复这些可复用的模式。能力成了学到的策略的一部分 36:34。

外壳工程（harness engineering）

改模型周围的系统：提示、工具、记忆、控制流。它提供上下文、校验、重试、安全边界。能力来自"模型 + 外壳"的组合 37:17。

课上举手，认为外壳更重要的人更多 35:50。讲师的看法是两者都重要。通常的演变是这样的。先在外壳里解决一个问题。等做模型的人发现这个问题够大，就把它训进模型。之后外壳就不用再管了 37:17。所以他更倾向把训练当根本解法。只是训练慢，常常得先用外壳顶上 38:02。

这像先打补丁、后发新版。补丁快，但新版才是根治。

9. MCP 真正的好处，是让智能体碰不到真凭据

MCP 服务器夹在智能体和上游 API 中间。智能体只拿一把无害的 MCP 密钥，真凭据留在服务器里。

MCP（Model Context Protocol）是 Anthropic 提出的标准，大约在一年半到两年前。它用来给模型提供额外的上下文 38:56。结构是这样的（讲义第 42 页）39:40。一个 AI 应用（MCP host）里开几个 MCP 客户端。每个客户端连一个 MCP 服务器。比如一个本地服务器，经标准输入输出（stdio）连文件系统。再比如一个远程服务器，经 HTTP 连过去。

讲师一开始觉得没必要 40:23。调 API 已经有好办法了，为什么还要多跑一个程序？讲义第 42 页也写着，MCP 是另一种面向智能体的接口。它不是调 REST API 的必需品。

FastMCP 之于 MCP，就像 FastAPI 之于 REST。把 FastAPI 换成 FastMCP，就能很快写一个 MCP 服务器。它也可以直接吃一份 OpenAPI 描述。每个路由都变成一个可被发现的 MCP 工具 41:06。讲义第 43 页的例子是 GET /weather 变成 get_weather(city, units)。

MCP 真正的好处是多一层安全 41:50。MCP 服务器有自己的 MCP 密钥，交给运行智能体的进程。上游 API 的密钥只交给 MCP 服务器，不交给智能体。比如你的 GitHub token。假如智能体拿着 GitHub token。某天它心血来潮，把 token 推到公开仓库，你的账号就沦陷了。给它一个相对无害的 MCP 密钥，即使泄露损失也小。真正的凭据被保护起来 42:34。讲义第 45 页把这叫作凭据中转（credential brokering）。服务器接受一种凭据，对上游用另一种凭据。模型两个秘密都看不到。

质量还有运行层面的维度（讲义第 55 页）50:3551:20：

  • 效率：延迟、调用次数、token、成本。正确但又慢又贵，也没法用。

12. 工具调用是一个五层的系统，每层管一件事

讲义第 59 页把这一讲收成五层 55:39：

  1. 能力工具带来检索、执行、生成、应用操作。正是它们让智能体成为智能体。
  2. 机制schema 进提示，模型按各自协议写出调用。外壳校验、分发、按 ID 匹配结果。
  3. 约束JSON Schema 和文法掩码保证形式，不保证语义正确。能解析的 Python 也可能是错的。
  4. 接口直接调 REST 和 MCP，是暴露能力、管理凭据的两种选择。
  5. 系统编排依赖和并发。评测选择、参数、结果、成本和运行时故障。
