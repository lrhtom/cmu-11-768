长上下文与上下文管理

1. 历史线性增长，送进模型的总量按平方增长

每次调用的输入，是固定前缀加上之前全部的动作和观察。所以历史线性增长，送进模型的总量按平方增长。

讲师一开始说，这一讲很多内容是通用的大模型知识 0:01。但长上下文对智能体特别重要。先修课又讲得不多，所以单独细讲 0:44。讲义第 3 页里，5 次调用的输入是 6K、11K、16K、21K、26K。加起来要处理 80K token 1:28。他自己用编程智能体时，一个会话连着用好几天的情况也有 2:11。

P, d, T = 6, 5, 5          # 讲义第 3 页：第一次 6K，之后每次多 5K，共 5 次（单位 K token）

2. 推理分两段：prefill 一口气读完，decode 一个一个写

推理先把全部输入一次读完，再一步只写一个 token。每写一个，它的 K、V 就追加进缓存。

长上下文有两个挑战（讲义第 5 页）4:18：

容量（capacity）

模型能不能用上需要的证据？这由结构、位置编码、训练数据决定，要靠评测来衡量。把模型训练到能处理超长上下文很难 4:184:58。

效率（efficiency）

系统供得起吗？注意力、KV 内存、缓存、压缩决定了成本和延迟。讲师提醒，平时用 Claude Code、Codex 觉得理所当然。背后其实是工程壮举。几万亿参数的模型，要在几秒内反复服务给海量用户。他说 Codex 有 2,500 万用户 4:585:39。

推理分两个阶段（讲义第 7–8 页）7:05：

阶段做什么瓶颈
Prefill（也叫编码）一次批量处理全部输入 token，它们不用生成。算出每个位置的 K、V 7:05。算力密集，延迟随提示长度增长
Decode每步读全部 K、V，生成一个输出 token。再把它的 K、V 追加进去，逐个递进。串行、内存带宽密集，每步只出一个 token
kv = ["kv%d" % i for i in range(6)]   # prefill：6 个提示 token 一次算出 K、V（示意）
for step in range(3):                  # decode：每步读全部 K、V，出一个 token
    kv.append("kv%d" % len(kv))        # 新 token 的 K、V 追加进缓存
print(len(kv), kv[-1])
# 输出: 9 kv8
# KV 缓存跟着请求走，越聊越大。decode 每步都要把它整个读一遍，所以吃显存带宽

这像餐馆出菜。prefill 是厨师一口气看完整张单子备料，decode 是一道一道往外端。

衡量一个推理服务的指标（讲义第 9 页）7:53：

  • TTFT（time to first token）：从请求到达，到看见第一个输出 token。输入越长，等得越久 7:53。
  • TPOT（time per output token）：相邻两个输出 token 的间隔。OpenRouter 上显示的每秒 token 数量的就是它，正好是它的倒数。讲师认为这个数不含 prefill。同一个 GLM 5.2，有的服务商每秒 63、48、24 个。有的只有 3 个，有的上百个。这对用智能体的体验差别巨大 8:359:15。
  • 吞吐：完成的 token 或请求数 ÷ 墙钟时间，看的是整个系统。成本：输入、缓存输入、输出 token 分别计费 10:51。

用法不同，在意的指标也不同。和编程 CLI 交互式地一起干活，TTFT、TPOT 非常重要。让智能体在后台通宵跑任务，可能完全不在乎。吞吐、成本和出 token 的速度之间有取舍。讲师的公司也在服务编程智能体。服务商常常问他更在意哪个，好针对性地优化 9:59。

4. 现在的模型几乎都是"几层局部 + 一层全局"

几乎所有省算力的结构都在做同一件事。给每一步的比较次数设个上限，再隔几层做一次全局计算。

现在的前沿模型上下文一般是 256K 到 100 万 15:05。大家都在往 100 万靠，谁也不想当那个"只有 256K"的模型。课上心算了一下。100 万长度的序列，两两比较大约 1012 次，也就是一万亿次。每次还是大向量相乘，单个序列就是天文数字的计算量 15:0515:47。

几乎所有解法都是同一个思路。每个时间步的比较次数，设一个常数上限。这样 O(n²) 就降到了 O(wn)。w 写成"窗口"，但不一定是窗口。只要是比较次数的上限就行 15:4716:32。

n, w = 1_000_000, 512
full, local = n * n, w * n          # 全注意力要两两比较，局部每步最多比 w 次
print(f"{full:.0e} {local:.0e} {full // local}")
# 输出: 1e+12 5e+08 1953

5. 线性注意力去掉 softmax，把整段历史压进一个固定大小的状态

滑动窗口只看附近几块。线性注意力干脆去掉 softmax，把整段历史累加进一个矩阵 S。每步只要常数时间更新。

滑动窗口注意力概念上最简单 18:36。把序列切成块，比如 512 token 一块。当前块只看自己和前面固定几块 19:19。注意力公式不用改。好处是层层叠加后，感受野会慢慢变大。第一层从前一两块拿信息。而前面的块在上一层，已经拿过它们更前面的信息 19:19。

讲义第 18 页：掩码 M(w)ij = 0 当 0 ≤ i − j < w，否则 −∞。代价是局部层不能直接取到远处的 token。

n, w = 6, 3
mask = [[0 if 0 <= i - j < w else "-inf" for j in range(n)] for i in range(n)]
print(mask[5])
# 输出: ['-inf', '-inf', '-inf', 0, 0, 0]
# 第 6 个位置只看自己和前 2 个。更远的信息只能靠下面几层一层层传上来

现在更流行的是各种线性注意力 20:02。标准注意力难算，是因为 softmax 要取指数再归一化。于是只能把所有查询和键两两乘一遍 20:0220:48。线性注意力干脆去掉 softmax，只留 qᵀk。

这确实让表达力更弱。softmax 能把一堆实数变成和为 1 的概率。这样模型就能只盯着少数相关的历史。这正是注意力的卖点。去掉它，就失去了"相对比较" 21:52。换来的好处是：乘法有结合律，可以把求和重排 22:34：

ot = tΣi=1(qtᵀki) vi = (Σi kiviᵀ)ᵀ qt = Stᵀ qt，  St = St−1 + ktvtᵀ讲义第 20 页。St 是 dk × dv 的固定大小矩阵。

S 是一个从查询映射到值的线性函数。注意力本来也是这样的函数。但 S 可以保留下来，每来一个新值就用常数时间更新。模型就变成了一个循环神经网络 22:3423:14。于是 O(n²) 直接变成 O(n)，连 w 都没有 23:57。

k, v, q = np.random.randn(5, 2), np.random.randn(5, 2), np.random.randn(2)
direct = sum((q @ k[i]) * v[i] for i in range(5))   # 去掉 softmax 后，直接两两乘
S = np.zeros((2, 2))
for i in range(5): S += np.outer(k[i], v[i])        # 递推：每来一个 token，S 加一次 k vᵀ
print(np.allclose(direct, S.T @ q))
# 输出: True
# 两种算法结果一样。递推版只存一个 2×2 的 S，不用留着全部历史

线性注意力像记账。不再每次翻遍所有旧账单，只在一本总账上累加。讲义第 20 页还提醒，这种状态只加不擦。旧的干扰不会被显式抹掉。

6. DeltaNet 先预测再改错，旧值被改写而不是越叠越多

DeltaNet 先用状态预测这个键对应的值，再只把误差写进去。同一个键的旧值被修正，不再累加。

后来的改进，数学上大多可以理解成一件事 24:40。让 S 成为对注意力输出更好的预测器。讲师按机制讲：

方法做法（讲义第 21–23 页）直观理解
DeltaNetv̂t = St−1ᵀkt，et = vt − v̂t。St = St−1 + βtktetᵀ。先用当前状态预测这个键对应的值，再只把误差写进去。修正后再用 kt 去读，就没有误差了。β 像学习率，防止一步改太大 25:2326:54。只沿 kt 方向修，无关的记忆保留。
Gated DeltaNetS̃t−1 = αtSt−1，再做同样的修正。αt ∈ [0, 1]。线性注意力没法阻止很久以前的怪键，一直影响后面的预测。所以每步让整个矩阵衰减一点 28:20。衰减越强，忘得越快，越"局部" 29:02。α = 1 就退回 DeltaNet。Qwen 用的就是它 29:47。
Kimi Delta Attention（KDA）Dt = Diag(αt)。St = (I − βtktktᵀ)DtSt−1 + βtktvtᵀ。每个通道一个衰减速度。有的部分记很久，有的很快忘。GLM 和 Kimi 用的是这种更有表达力的版本 29:47。
k, v_new = np.array([1.0, 0.0]), np.array([1.0, 2.0])
S = np.outer(k, [5.0, 5.0])                    # 键 k 下原来存的值是 [5, 5]
S_lin = S + np.outer(k, v_new)                 # 线性注意力：只加不擦
S_delta = S + np.outer(k, v_new - S.T @ k)     # DeltaNet（β = 1）：只把误差写进去
print(S_lin.T @ k, S_delta.T @ k)
# 输出: [6. 7.] [1. 2.]
# 用同一个键去读：线性注意力读出旧值加新值，DeltaNet 读出的正好是新值
# Gated DeltaNet 再在修正前把 S 乘上 α，整张表一起慢慢褪色

线性注意力像在便利贴上不停叠着写。DeltaNet 像先擦掉同一格的旧字，再写新的。Gated 版还让整张纸慢慢褪色。

一句话总结。这些方法都是把注意力变成能在上下文里递推的东西。Mamba 思路类似，但数学更复杂，讲师跳过了 30:28。

7. 稀疏注意力少看一些，KV 压缩少存一些

稀疏注意力只挑一部分历史来看。KV 压缩让每个 token 存的 K、V 变小。

稀疏注意力不看全部历史，只看其中一部分，并限制看的数量 31:14（讲义第 24 页）：

固定模式

和输入无关，比如每隔 512 个 token 看一个。仍然是平方复杂度，但比全看少 512 倍。这已经够在需要的长度上算了 31:1431:57。代价可预测，但不会随查询调整。

和内容相关

先用很便宜的方式算一遍注意力。比如把向量投影到很小的维度。挑出 top-K 个位置，再在这 K 个上做完整注意力。DeepSeek 用的是这种 31:5732:37。它能自适应，但选择器选错就会漏掉相关的键。要算两遍，但可能更准 33:23。

scores = np.array([0.1, 2.0, -1.0, 3.0, 0.5, 2.5])   # 用便宜的低维投影先打一遍分（示意）
topk = np.argsort(scores)[-2:]                        # 只挑分最高的 K = 2 个位置
print(sorted(topk.tolist()))
# 输出: [3, 5]
# 再只在这 2 个位置上做完整注意力。位置 1 的分也不低，被挤掉了

课上有同学问，挑 top-K 用的是不是余弦相似度？讲师说一般就是点积，也可能事先归一化过，他不确定细节 32:37。

KV 压缩（讲义第 25 页）33:23。标准的多头注意力（MHA）每个头都有自己的 K、V，KV 缓存很大。大到会限制一张卡能同时服务多少请求 34:49。

做法怎么省
GQA（分组查询注意力）K、V 的组数比头数 H 少，通常是 H 除以 2 的幂。KV 缓存一般能省到 1/4、1/8 34:0534:49。
MQA（多查询注意力）GQA 的极端：所有头共用一组 K、V。
MLA（多头潜在注意力）不减头数，而是把每个头的 K、V 降维。缓存一个小的潜变量 ctKV，用时再投影回各头的 K、V 34:4935:37。
H, d, n = 32, 128, 100_000                          # 头数、每头维度、上下文长度（示意）
kv_mb = lambda groups: 2 * groups * d * n * 2 // 2**20   # K 和 V，fp16 每个数 2 字节，单层，单位 MB
print([kv_mb(g) for g in (H, H // 8, 1)])           # MHA、GQA（8 个头共用一组）、MQA
# 输出: [1562, 195, 48]

稀疏注意力像考前只翻重点页。KV 压缩像把笔记缩印。这些可以组合使用。靠这些结构手段，模型能处理到 100 万 token 35:37。

8. 长上下文要靠连贯的长数据，位置编码还得能外推

长上下文训练的关键有两样。一是连贯的长数据，二是能外推到更长的位置编码。

训练长上下文很难。互联网上连贯的 128K token 数据并不多。那已经是一本书的长度了 36:22。所以通常分阶段训练（讲义第 27 页）37:04：

  1. 短的预训练4K–8K，数据多、成本低
  2. 用更长文档继续训练32K–128K
  3. 长适配128K 以上：任务轨迹、合成课程

讲师特别纠正了讲义上写的"打包序列" 37:04。把 10 篇文档塞进一个序列，能提高效率。也能教模型处理窗口末尾的位置。但它学不到跨文档的长程关联，本来也不该跨文档关联。要真正适配长上下文，需要连贯的长数据 46:18。

9. 上下文并行把一条长序列切给几台设备，K、V 轮流传

上下文并行把一条很长的序列切成几段，每台设备算一段。K、V 沿着环一台传一台。

做项目想训大一点的模型时会碰到它 49:05。课上先复习了几种并行 49:51：

  • 数据并行。
  • 专家并行：不同专家放不同机器。
  • 张量并行：切参数。
  • 流水线并行：不同层放不同设备。

后三种都是模型并行。上下文并行对智能体越来越重要。智能体要在很长的上下文上训练 50:33。一台设备算一段上下文的 K、V，传给下一台。下一台再算自己那段，依次传下去。超过约 32K 上下文就很重要了。讲义第 36 页的 Ring Attention：每台设备内存 O(ndh/P)。通信和块注意力重叠。总计算仍是精确的 O(n²dh)。

P = 4
seen = [{dev} for dev in range(P)]                 # 每台设备先只有自己那段的 K、V
for step in range(1, P):                           # 每一步把手里的 K、V 传给下一台
    for dev in range(P): seen[dev].add((dev - step) % P)
print([sorted(s) for s in seen][:2])
# 输出: [[0, 1, 2, 3], [0, 1, 2, 3]]
# 传 P-1 步后每台都见过全部 K、V，结果仍是精确的全注意力。每台只存 1/P 的序列

3. 能存的经验有三种：经历、事实、技能

经历是整条录像。事实是一句关于环境或用户的话。技能是去掉细节后的"怎么做"。

讲义第 4 页的三类经验 9:05：

经历（episode）

完整的观察和动作序列。保真度最高，保留了环境和指令的全部细节。也最贵，最费 token，而且大多用不上。就像监督学习，要抽象出对泛化重要的东西 9:47。适用于具体的商品、价格或顺序还会再用到时。

事实（fact）

关于环境或用户的知识。比如"这家店只在商品页显示价格"，用户多大、住哪。早期记忆系统多是存事实。ChatGPT、Claude 的"记忆"功能也是这样。设置里能看到这些文字，是模型从你过去的对话里写出的。有点像压缩 10:27。

技能（skill）

任务中可复用的一部分怎么做，并且和具体细节分开。只记"怎么搜"，不记"搜了什么"。可以是文本、实际动作，甚至代码。只有同一个子任务会反复出现时才有用 11:11。

episode = [("type", "search_box", "Sony headphones"), ("click", "search_btn", ""), ("read", "price", "$58")]

print(len(episode), skill)
# 输出: 3 [('type', 'search_box', '{query}'), ('click', 'search_btn', '')]
# 经历整条原样存，最全也最占地方。技能只留"怎么搜"，搜了什么换成变量（示意）

三类经验像三种笔记。经历是录像，事实是便利贴，技能是菜谱。

记忆和技能有交集（讲义第 5 页）11:52。记忆是从智能体自己的交互里存下来的。比如之前买过的商品。技能是关于怎么做的可复用知识。比如人写的"上线前检查清单"。两者的交集是归纳出的技能。也就是从智能体自己成功的经历里抽出来的技能 12:33。技能有两种来源（讲义第 6 页）：

作为指令的技能作为学习的技能
作者人或组织（个人偏好、公司规范）智能体

强项意图和来历清楚，质量更可控 13:15能自动化：归纳 → 用它重做任务 → 看指标有没有变好
主要负担专家写和维护都费时间评判结果、验证、整理。可能有噪声，用到别的智能体上还可能有意外后果。

  • 人写或安装的。放进仓库的 .agents/skills/，或者从别的仓库、注册表装。

只能往里加是不够的 34:50。你说过"我在 X 公司工作"，后来换了工作。系统应该用最新的信息。Mem0 引入了记忆更新（讲义第 18 页）35:32。流程分三步。先用 LLM 从每条新消息里抽出可能要存或要改的事实。再用嵌入检索，从数据库里取出最相似的 top-k 条旧记忆。最后让 LLM 对比，选一种操作：

ADD还没存过类似的

直接训练技能归纳器（讲义第 43 页）1:12:44。前面这些都有点"临时拼凑"。都是提示语言模型，去预测以后可能有用的东西。能不能直接训练它去做？可以，这是刚刚开始的方向，今年 ACL 上的论文。做法是在一串相似的任务上做强化学习。像前面评测那样，边做边归纳，边用记忆 1:13:25。整个过程很复杂。用了好几个模型，要存取记忆。但强化学习不在乎，它能用在这种不可微的复杂流程上。

难点在奖励。任务 1 的奖励只说明任务 1 成没成功。它说明不了存下的这部分解法值不值。只有后面的任务能说明。所以把后面的任务放进同一个训练样本里。SAGE 在一次 rollout 里放两个相关任务。AgeMem 用一条长轨迹。奖励里再加上"后面的任务复用了它的技能" 1:14:08：

任务 1 的奖励 = r1 + 𝟙[两个都成功] · 𝟙[任务 2 复用了它的技能]（讲义第 43 页）

def task1_reward(r1, both_ok, reused):   # 讲义第 43 页：后面的任务复用了它的技能才加分
    return r1 + int(both_ok) * int(reused)
print(task1_reward(1, True, True), task1_reward(1, True, False))
# 输出: 2 1
# 只看 r1 的话，两种情况一样高。加上复用项，模型才会学着存真正有用的技能
