编程智能体

2. 预训练要混代码和文字，还得保住空白和缩进

3. 中期训练多加代码、拉长上下文，通用能力不能丢

中期训练把通用模型改造成编程模型。做法是加大代码比例，再把相关文件拼成连贯的长序列。

deps = {"caller.py": "worker.py", "worker.py": "types.py", "types.py": None}   # 谁依赖谁
depth = lambda f: 0 if deps[f] is None else 1 + depth(deps[f])
print(" + ".join(sorted(deps, key=depth)))     # 被依赖的排前面，拼成一条长序列
# 输出: types.py + worker.py + caller.py
# 踩坑：按文件名字母序拼，caller.py 排第一。模型先看到判空，后看到 Result 的定义
# 这样学不到跨文件的联系

4. 填空就是把中间那段挪到末尾，再照常从左往右学

填空（infilling）是补中间缺的一段。做法是把缺的那段挪到末尾，模型照常从左往右学。

prefix, span, suffix = "def is_positive(x: int) -> ", "bool", ": return x > 0"
train = prefix + "[M0]" + suffix + "[M0]" + span + "[END]"   # 训练：空挪到最后，照常学下一个 token
infer = prefix + "[M0]" + suffix + "[M0]"                    # 推理：给到这里，让模型接着写 span
print(train)
print(train.startswith(infer))
# 输出: def is_positive(x: int) -> [M0]: return x > 0[M0]bool[END]
# 输出: True
# 写 span 的时候，右边的 suffix 已经在前面了。所以右边的上下文也能用上
# 学会填空也不损害普通的从左到右补全

5. 评代码要真跑测试，长得像不等于做得对

评测生成的代码，现在主流是真跑。候选代码加测试用例，放进隔离环境里跑，全过记 1，否则记 0。

ref = set("return x > 0".split())
for cand in ["x >= 0", "not (x <= 0)"]:
    overlap = len(ref & set(("return " + cand).split())) / len(ref)   # 像不像：数 token 重叠
    passed = all(eval(cand, {"x": v}) == (v > 0) for v in (-1, 0, 1))  # 对不对：真跑三个输入
    print(cand, overlap, passed)
# 输出: x >= 0 0.75 False
# 输出: not (x <= 0) 0.25 True

def resolved(self) -> bool:

    if self.error or not self.fail_to_pass:
        return False
    graded = {**self.fail_to_pass, **self.pass_to_pass}
    return all(status is TestStatus.PASSED for status in graded.values())

9. CUA 模型从截图和动作交错的历史里，预测下一个动作

CUA 就是一个视觉语言模型。它的输入是目标，加上截图和动作交错的历史。输出是下一个动作的文字。

history = ["goal: buy a blue mug", "shot0"]                         # 第 0 步：目标 + 截图 0
for action, shot in [("click(33, 201)", "shot1"), ("scroll(520)", "shot2")]:
    history += [action, shot]                                       # 动作和新截图都接到后面，越拼越长
print(history)
# 输出: ['goal: buy a blue mug', 'shot0', 'click(33, 201)', 'shot1', 'scroll(520)', 'shot2']
# 截图进模型前会过视觉编码器，变成一串视觉 token，不是一个字符串
reply = "The CAR tab is at the top. click(500, 250)"             # 示意：模型先写推理，再写动作
x, y = map(int, re.search(r"click\((\d+), (\d+)\)", reply).groups())   # 外壳从文字里抠出动作
for w, h in [(2560, 1440), (1280, 720)]:                         # 坐标归一化到 0–1000，换分辨率照样用
    print(round(x / 1000 * w), round(y / 1000 * h))
# 输出: 1280 360
# 输出: 640 180
# 踩坑：各家动作格式都不一样。外壳解析不了，动作就执行不了

打个比方。这像看连环画续写。每一格是一张截图，格子之间写着上一步做了什么。模型看完前面所有格，写出下一步的动作。

CUA 就是一个按某种格式接收输入的 LLM。因为要看截图，通常是视觉语言模型 48:52。第 0 步，目标和截图 0 进策略（讲义第 47–55 页）。策略输出文本形式的结构化动作，比如带 x、y 的点击 49:35。执行后，把动作和新截图都接到上下文后面，再预测下一个。这就是 ReAct 循环 50:17：
