query_language_model 已经写好，它依次做这几件事：

  • 调 build_prompt()，把结果深拷贝存进 api_prompts。这是评分用的，不许动。
  • 带上 self.tools、reasoning_effort="medium"、max_completion_tokens=4096 发请求。

def query_language_model(self) -> dict[str, Any]:
    """Send one tool-enabled Chat Completions request and normalize it."""

    messages = self.build_prompt()
    self.api_prompts.append(deepcopy(messages))
    step_number = self.steps_taken + 1
    print(
        f"[agent] step {step_number}/{self.step_limit}: requesting action",
        flush=True,
    )
    try:
        response = self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            tools=self.tools,
            reasoning_effort="medium",
            max_completion_tokens=4096,
        )
    except Exception as exc:
        print(
            f"[agent] step {step_number}: model request failed after retries "
            f"({type(exc).__name__}: {exc})",
            flush=True,
        )
        raise
    self.api_responses.append(response.model_dump(mode="json"))
    self.steps_taken += 1
    message = self.process_response(response)
    tool_names = [
        call.get("function", {}).get("name", "unknown")
        for call in message.get("tool_calls", [])
        if isinstance(call, dict)
    ]
    if tool_names:
        print(
            f"[agent] step {step_number}: tool call(s): {', '.join(tool_names)}",
            flush=True,
        )
    else:
        print(
            f"[agent] step {step_number}: response contained no parsed tool call; "
            "the loop should preserve the response and continue",
            flush=True,
        )
    return message

几个容易想错的地方：

  • 只有文字，没有工具调用。模型有时只"描述"它要做什么。这时 query_language_model 会打印"the loop should preserve the response and continue"。意思是保留这条回复，继续循环。评分表里的 text-only recovery 就是这个。示意实现在后面加一条 user 消息，提醒它调工具。
  • 步数怎么数。steps_taken 只在 query_language_model 里加，压缩请求不算。检查放在请求之前，所以恰好发出 step_limit 次请求。公开测试 test_step_limit_raises 数的就是请求次数。
  • 谁来设 finished。循环本身不知道"完成"是什么，由子类在执行工具时设。CodeAgent 在 send_message 时设，ChessAgent 在棋局 game_over 时设。ChessAgent 构造时如果对局已经结束，循环一圈都不跑。

执行要走 Environment.execute，确保命令在正确的 Modal 沙箱里跑。它返回三项：output（stdout 后接 stderr）、returncode、exception_info。三种情况分开处理：

  • 命令退出码非零：只报告，不抛异常。
  • 命令本身出了问题，比如超时：returncode 是 −1，exception_info 写原因。
  • 沙箱已经死了：抛 RuntimeError。因为之后每条命令都会同样失败。

可选参数默认用它自己的值。但模型在调用里给了，就要传过去。

def execute(
    self,
    command: str | list[str],
    timeout: float | None = None,
    cwd: str | None = None,
    env: dict[str, str] | None = None,
    # Command defaults to shell=False, which requires `command` to be an argv
    # list; default to shell=True so a plain command string works.
    shell: bool | None = True,
    # check=False so a failing command returns its exit code instead of
    # raising and discarding the output the agent needs to see.
    check: bool = False,
) -> dict:
    """Run a command in the sandbox and return its result.

    Args:
        command: A shell string, or an argv list if `shell` is False.
        timeout: Seconds before the command is killed. None means no timeout.
        cwd: Working directory to run the command in. Defaults to the
            environment's `cwd`.
        env: Environment variables to set for the command.
        shell: Run the command through a shell, as with `subprocess.run`.
            None is treated as True, since a model calling this as a tool may
            send null for an omitted argument.
        check: Raise on a non-zero exit code instead of reporting it.

    Returns:
        A dict with `output`, `returncode`, and `exception_info`. `output`
        holds stdout and stderr interleaved, as they would appear in a
        terminal. `exception_info` is empty when the command ran, whatever
        its exit code. If the call itself fails (the sandbox died, the
        command timed out), the exception is caught rather than raised:
        `returncode` is -1, `exception_info` describes it, and an `extra` key
        carries the exception type.
    """
    # Command.shell is a strict bool, so None would fail validation.
    shell = True if shell is None else shell

    arguments = {
        "command": command,
        "timeout": timeout,
        "env": {**self.env_defaults, **(env or {})} or None,
        "shell": shell,
        "check": check,
        "merge_output_streams": False,
    }
    if cwd is not None:
        arguments["cwd"] = cwd
    # A cwd from the caller wins; otherwise the environment's default applies.
    arguments.setdefault("cwd", self.cwd)

    try:
        result = asyncio.run(self.deployment.runtime.execute(Command(**arguments)))
        output = {
            "stdout": result.stdout,
            "stderr": result.stderr,
            # The coding agent consumes one observation string, while the
            # task harness needs the streams separately for diagnostics.
            "output": result.stdout,
            "returncode": result.exit_code,
            "exception_info": "",
        }
        if result.stderr:
            output["output"] += result.stderr
    except Exception as e:
        # A command can fail for reasons worth reporting to the model, but a
        # sandbox that is gone is terminal: every later command fails the
        # same way, so raise rather than let the caller keep going.
        if not self.is_alive():
            raise RuntimeError(
                "The sandbox is no longer running, so no further commands can "
                f"be executed. Last error: {e}"
            ) from e

        # NOTE(source): https://github.com/SWE-agent/mini-swe-agent/blob/a83fcae82d2a08f0ee0c688f9d137b3566c097f8/src/minisweagent/environments/extra/swerex_modal.py#L82-L87
        # Same keys as the success path, so callers never have to branch on
        # which one they got.
        output = {
            "stdout": "",
            "stderr": str(e) if str(e) else "",
            "output": str(e) if str(e) else "",
            "returncode": -1,
            "exception_info": f"An error occurred while executing the command: {e}",
            "extra": {"exception_type": type(e).__name__, "exception": str(e)},
        }
    return output

def format_tool_output(output: dict[str, Any]) -> str:
    """Format a terminal result as a compact, tagged model observation."""

    elements: list[str] = []
    for key in sorted(output):
        value = output[key]
        if isinstance(value, str) and len(value) > MAX_OBSERVATION_CHARS:
            # Leave room for the elision notice so the formatted value itself,
            # not just its retained source slices, stays below the limit.
            retained_at_each_end = 4_900
            omitted = len(value) - (2 * retained_at_each_end)
            value = (
                f"{value[:retained_at_each_end]}\n"
                f"[{omitted} characters elided; read a narrower range]\n"
                f"{value[-retained_at_each_end:]}"
            )
        elements.append(f"<{key}>{value}</{key}>")
    return "\n".join(elements)

def execute_tool_calls(
    self, tool_calls: list[dict[str, Any]]
) -> list[dict[str, str]]:
    """Execute ``execute`` and ``send_message`` calls in the code sandbox."""

    # 示意实现 1.3：一个调用一条 tool 消息，按 tool_call_id 接回；
    # 坏 JSON / 未知工具变成可恢复的观察，不抛异常。
    names = {t["function"]["name"] for t in self.tools}
    observations = []
    for call in tool_calls:
        fn = call.get("function") or {}
        name, raw = fn.get("name"), fn.get("arguments") or "{}"
        try:
            args = json.loads(raw) if isinstance(raw, str) else raw
            if not isinstance(args, dict):
                raise ValueError("arguments must be a JSON object")
        except ValueError as exc:  # JSONDecodeError 也是 ValueError
            content = format_tool_output(
                {"error": f"could not parse arguments for {name}: {exc}"})
        else:
            if name not in names:
                content = format_tool_output({"error": (
                    f"unknown tool {name!r}; available: "
                    f"{', '.join(sorted(names))}")})
            elif name == "execute":
                content = self._execute(args)
            elif name == "send_message":
                content = self._send_message(args)
            else:  # invoke_skill
                content = self._invoke_skill(args)
        observations.append({
            "role": "tool",
            "tool_call_id": call.get("id", ""),
            "content": content,
        })
    return observations

def _execute(self, args: dict[str, Any]) -> str:
    command = args.get("command")
    ok = isinstance(command, str) or (
        isinstance(command, list)
        and all(isinstance(part, str) for part in command))
    if not ok or not command:
        return format_tool_output(
            {"error": "`command` must be a string or a list of strings"})
    options = {key: args[key] for key in ("shell", "cwd", "timeout", "env")
               if args.get(key) is not None}
    result = self.env.execute(command, **options)
    shown = {"output": result.get("output", ""),
             "returncode": result.get("returncode")}
    if result.get("exception_info"):
        shown["exception_info"] = result["exception_info"]
    return format_tool_output(shown)

def _send_message(self, args: dict[str, Any]) -> str:
    summary = args.get("summary")
    if not isinstance(summary, str):
        return format_tool_output({"error": "`summary` must be a string"})
    patch = self.env.execute("cat patch.txt")
    if patch.get("returncode") == 0:
        self.submitted_patch = patch.get("output", "")
    self.finished = True
    return format_tool_output({"status": "message delivered; session over"})

def _invoke_skill(self, args: dict[str, Any]) -> str:
    name = args.get("name")
    if not isinstance(name, str) or name not in self.skills:
        known = ", ".join(sorted(self.skills))
        return format_tool_output(
            {"error": f"unknown skill {name!r}; available: {known}"})
    return self.skills[name]["content"]

def load_skills(self, skills_path: Path) -> dict[str, dict[str, str]]:
    """Load the skill folders exposed to this agent."""

    # 示意实现 1.4：一个子目录一个 SKILL.md，按 frontmatter 的 name 建表。
    if not skills_path.is_dir():
        raise ValueError(f"skills_path {skills_path} is not a directory")
    skills: dict[str, dict[str, str]] = {}
    for folder in sorted(p for p in skills_path.iterdir() if p.is_dir()):
        file = folder / "SKILL.md"
        if not file.is_file():
            raise ValueError(f"{folder} has no SKILL.md")
        content = file.read_text(encoding="utf-8")
        match = FRONTMATTER.match(content)
        if not match:
            raise ValueError(f"{file}: missing --- frontmatter ---")
        try:
            meta = yaml.safe_load(match.group(1))
        except yaml.YAMLError as exc:
            raise ValueError(f"{file}: malformed frontmatter") from exc
        if not isinstance(meta, dict):
            raise ValueError(f"{file}: frontmatter is not a mapping")
        name, desc = meta.get("name"), meta.get("description")
        if not (isinstance(name, str) and name.strip()):
            raise ValueError(f"{file}: frontmatter needs a name")
        if not (isinstance(desc, str) and desc.strip()):
            raise ValueError(f"{file}: frontmatter needs a description")
        name = name.strip()
        if name in skills:
            raise ValueError(f"duplicate skill name {name!r}")
        skills[name] = {
            "metadata": f"name: {name}\ndescription: {desc.strip()}",
            "content": content,
        }
    return skills

def maybe_compact_context(self) -> bool:
    """Compact before the next action request when the threshold is reached."""

    if not self.compaction_enabled:
        return False

    # Context too short to compact yet
    if self.estimate_active_prompt_tokens() < self.compact_threshold_tokens:
        return False

    prompt_before = deepcopy(self.build_prompt())

    # Not enough steps (each assistant turn corresponds to a step) to force
    # compaction yet
    if (
        len([m for m in prompt_before if m.get("role") == "assistant"])

def estimate_active_prompt_tokens(self) -> int:
    """Estimate the next prompt, calibrated by the provider's latest usage."""

    current_prompt = self.build_prompt()
    rough_current = rough_message_tokens(current_prompt)
    if not self.api_prompts or not self.api_responses:
        return rough_current

    usage = self.api_responses[-1].get("usage") or {}
    actual_previous = usage.get("prompt_tokens")
    if not isinstance(actual_previous, int):
        return rough_current

    rough_previous = rough_message_tokens(self.api_prompts[-1])
    added_since_previous_request = max(0, rough_current - rough_previous)
    return actual_previous + added_since_previous_request

class SimulationRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    fen: str = Field(min_length=1, max_length=200)
    move: str | None = Field(default=None, min_length=4, max_length=5)

def simulate_position(fen: str, move: str | None = None) -> dict:
    """Inspect a position or apply exactly one legal ply, for either color.

    FEN preserves turn, castling, en passant, and move counters, but not a
    repetition history. Repetition-based draws cannot be inferred here.
    """
    try:
        if len(fen.split()) != 6:
            raise ValueError("Expected all six FEN fields.")
        board = chess.Board(fen)
        if not board.is_valid():
            raise ValueError("The FEN describes an invalid chess position.")
    except ValueError as exc:
        raise ValueError(f"Invalid FEN: {exc}") from exc

    # Unlike the live game, no repetition history or automatic bot is involved.
    outcome = board.outcome(claim_draw=True)
    applied_move = None
    if move is not None:
        if outcome is not None:
            raise ValueError("Cannot move in a terminal position.")
        try:
            candidate = chess.Move.from_uci(move)
        except ValueError as exc:
            raise ValueError("Move must use UCI notation, including a promotion suffix.") from exc
        if candidate not in board.legal_moves:
            raise ValueError(f"{move} is not legal in the supplied position.")
        board.push(candidate)
        applied_move = candidate.uci()
        outcome = board.outcome(claim_draw=True)

    winner = None if outcome is None or outcome.winner is None else (
        "white" if outcome.winner else "black"
    )
    turn = "white" if board.turn else "black"
    return {
        "fen": board.fen(en_passant="fen"),
        "squares": {chess.square_name(s): p.symbol() for s, p in board.piece_map().items()},
        "turn": turn,
        "legal_moves": sorted(m.uci() for m in board.legal_moves) if outcome is None else [],
        "in_check": board.is_check(),
        "game_over": outcome is not None,
        "winner": winner,
        "result": outcome.result() if outcome else "*",
        "termination": outcome.termination.name.lower() if outcome else None,
        "status": (f"{winner.title()} wins" if winner else "Draw") if outcome else f"{turn.title()} to move",
        "applied_move": applied_move,
        "simulation": True,
        "repetition_history_available": False,
    }

def build_tools(client: httpx.Client) -> dict:
    """Expose the registered tools under the names the model was taught."""

    def unwrap(result):
        # The tool layer reports a failed call as an observation. A snippet
        # wants an exception at the line that caused it.
        if isinstance(result, str):
            if result.startswith("<chess_error>"):
                raise RuntimeError(result)
            return json.loads(result)
        return result

    def simulate_move(fen: str, move: str | None = None) -> dict:
        return unwrap(_simulate_move(client, json.dumps({"fen": fen, "move": move})))

    def play_move(move: str) -> dict:
        return unwrap(_play_move(client, json.dumps({"move": move})))

    return {"simulate_move": simulate_move, "play_move": play_move}

def main() -> None:
    port, encoded = sys.argv[1], sys.argv[2]
    code = base64.b64decode(encoded).decode()
    client = httpx.Client(base_url=f"http://127.0.0.1:{port}", timeout=30)

    namespace = {"__name__": "__agent__", **build_tools(client)}
    stdout, stderr = io.StringIO(), io.StringIO()
    error = None
    with redirect_stdout(stdout), redirect_stderr(stderr):
        try:
            exec(compile(code, "<agent-python>", "exec"), namespace, namespace)
        except BaseException as exc:
            error = f"{type(exc).__name__}: {exc}"
            traceback.print_exc(limit=4)

    # The result is the only thing on the real stdout, so the caller can parse
    # it whatever the snippet printed.
    json.dump(
        {"stdout": stdout.getvalue(), "stderr": stderr.getvalue(), "error": error},
        sys.__stdout__,
    )

if __name__ == "__main__":
    main()

        if name not in names:

                       f"{', '.join(sorted(names))}</chess_error>")

                moved or self.finished):

                self.last_state = state

3. 每个错误归四类之一，再带一句具体证据

validate(run) 返回一个错误列表，空列表表示可以接受。这一节依据 ASSIGNMENT.md 的 "What counts as each error"，和 validator/prediction.py、seed_labels.json。每个错误是固定四类之一。还要附一段证据（evidence），取自这次运行。一个运行可以同时有几类错误。

类别算什么
execution_failure最后没产出有效的图。总是单独出现
wrong_data画的不是要求的数据。数值错：聚合、缩放、归一化、取样区间、气泡大小、颜色值、误差棒。缺数据：缺系列、类别、面板、点，或者 3D 少一维。选错了子集、列、过滤条件，或者混进没要求的系列。顺序错：要求排序没排、序列反了、面板放错数据
wrong_chart数据对，但没照要求的图表设计。图表类型和投影不对。比如该柱用了线，该堆叠用了分组，该 3D 画成 2D。也包括极坐标、等高线、双轴、放大插图。布局：子图数量和排列、尺寸或 DPI、共享坐标轴。坐标轴：标签、标题文字、范围、刻度方式。还有刻度标签及旋转、边框、网格。图例、色条、标注也算。样式：色图、线型、标记、指定系列的颜色、填充。还有箱线图的须和中位线、多边形闭合
hard_to_read照要求画了，但读不了或很难读。文字被图片边缘切掉一部分。文字互相重叠，或者标记压住标签。图例、注释盖住数据或文字，盖在空白处没事。对比度低于约 2.5:1，或者系列画成背景色、零宽度。两个要区分的系列，颜色、线型、标记几乎一样。数据被挤成一条缝

两条边界规则。第一条管文字跑到图外。要求的标题或坐标轴标签完全在图外，算"缺失"，归 wrong_chart。被边缘切掉一半，归 hard_to_read。第二条管终止。execution_failure 在标签里是终止性的。人工标签说没有有效图时，另外三类对这个运行不计分。反过来不成立。判卷器预测了 execution_failure，这个运行照样要算另外三类。

4. 每类单独算 MCC，四个取平均，常数预测得 0

判卷器的成绩是四类各算一个 MCC，再取平均。这一节依据 ASSIGNMENT.md 的 Evaluation format 和 workflow/evaluate.py 的 score。每一类单独当成一个二分类问题。真实标签里有这一类，就是正例。判卷器的错误列表里有这一类，就是预测为正。在参与这一类的运行上数出 TP、TN、FP、FN，算马修斯相关系数（MCC）：

MCC = TP · TN − FP · FN√(TP + FP)(TP + FN)(TN + FP)(TN + FN)1 是完全分对。0 是预测和真相无关，跟瞎猜一样。负数是反着来。范围是 [−1, 1]

总分 macro_mcc 是四类 MCC 的简单平均，分母永远是 4。有两个约定。第一，真实标签两种都有、预测却是常数时，MCC 记 0。第二，某一类的真实标签只有一种，也按 0 记。比如自己的小数据集里，这类错误从没出现过。这时会标出"支持度不足"（insufficient support）和正负样本数。私有评分集每类都有正负两种，这条不影响正式成绩。但分析自己的题时要当心。

def mcc(tp, tn, fp, fn):
    d = math.sqrt((tp + fp) * (tp + fn) * (tn + fp) * (tn + fn))
    return 0.0 if d == 0 else (tp * tn - fp * fn) / d  # 分母为 0 按约定记 0

上下文太长时有一条退路。先发完整证据。服务器报"超出上下文"时，警告一次，然后只重试一次缩短版。缩短的做法是这样的：

  • 预算用服务器的分词器（vLLM 的 /tokenize、/detokenize）和上下文上限来算。
  • 50% 的上下文留给文字和回答，这个比例是 CONTEXT_FRACTION。回答最多 250 token。
  • 预算按比例分给轨迹和输入文件。两者各自保留开头和结尾，中间写"[... omitted to fit model context ...]"。
  • 再提醒模型，省略的部分不算智能体的错。
  • 任务文字和图片保持完整。文字缩短后还超，就缩图片。长边每次乘 0.7，直到最长边 64 像素为止。

第二道是 solve.sh 模板直接 exit 1。test.sh 的写法也有讲究。它故意不用 set -e，否则 pytest 失败时脚本直接退出，reward 没写。它用 ${PIPESTATUS[0]} 而不是 $?。$? 是 tee 的退出码，几乎总是 0，那就成了"失败也给 1"：

  -rA -q --no-header \
  --ctrf /logs/verifier/ctrf.json 2>&1 | tee /logs/verifier/pytest.log

# PIPESTATUS[0], not $?: $? is tee's exit status, and tee essentially always
# succeeds. Reading $? here would hand out reward 1 for every failed run --
# a fail-OPEN verifier, the exact bug `harbor init`'s scaffold ships with.
if [ "${PIPESTATUS[0]}" -eq 0 ]; then
  echo 1 > /logs/verifier/reward.txt
else
  echo 0 > /logs/verifier/reward.txt
fi
echo "[test.sh] reward=$(cat /logs/verifier/reward.txt)"
pytest_exit, tee_exit = 1, 0                # pytest 失败了，管道后面的 tee 照样成功
reward_bad = 1 if tee_exit == 0 else 0      # 读 $?：拿到的是 tee 的退出码
reward_good = 1 if pytest_exit == 0 else 0  # 读 PIPESTATUS[0]：拿到的是 pytest 的

# 输出: 1 0

训练数据的单位是 TokenSequence。它的三个并列列表都比 tokens 短 1。因为训练预测的是"下一个 token"：

@dataclass
class TokenSequence:
    """A stitched training sequence, the unit of training data.

    `tokens` is the full sequence [t_0, ..., t_{n-1}] (initial prompt with
    completions and env observations interleaved). Training predicts the
    *next* token, so the targets are tokens[1:], and the three parallel lists
    below all have length n - 1, aligned with the targets:

        mask[j]       = 1 iff tokens[j+1] was sampled from the policy
        logprobs[j]   = sampling logprob of tokens[j+1]  (0.0 where mask == 0)
        advantages[j] = advantage credited to tokens[j+1] (0.0 where mask == 0)

    Loss is only applied where mask == 1: we don't train the model to imitate
    environment observations, only reinforce (or suppress) its own actions.
    """

    tokens: list[int]
    mask: list[int]
    logprobs: list[float]
    advantages: list[float]

一整个多轮回合能拼成一条训练序列，靠的是"序列延伸"。智能体在 token 空间里维护提示。每一轮只在上一轮"提示 + 补全"的后面，追加新渲染的尾巴。尾巴包括轮次标记、环境观察、下一轮的生成提示。这在 c6 的 RL 系统一讲（第 12 讲）里讲过。那里的演示也动画演示了拼接和 Token-In Token-Out，这里不再重复。

5. GRPO 的优势就是奖励减组均值，全一样就跳过

作业用的优势很简单。REINFORCE 直接用奖励，GRPO 用奖励减去同组的平均。这一节依据 ASSIGNMENT.md 的 Background 和 tinker_adapter.py 的 train_step。公式和第 5、6 章讲的一样，这里只列作业用到的形式。

设拼好的回合有 token t0 … tn−1。mj ∈ {0, 1} 标记目标 tj+1 是不是策略采样出来的。它为 0 时，这个 token 是提示或环境给的。整个回合共用一个优势 A：

∇θJ(θ) = 𝔼[ A Σj: mj = 1 ∇θ log πθ(tj+1 | t≤j) ]只有策略自己采样的 token 进损失。掩码要是混进观察 token，模型就在学"预测环境"，而不是"行动"

REINFORCE：A = r　　GRPO：Ai = ri − 1G GΣk=1 rkG 是同一题的一组采样数。不除以组内奖励的标准差，也不加对参考策略的 KL 惩罚。作业文档说这是照 Dr.GRPO 的做法

REINFORCE 无偏，但噪声大。成功回合的每个采样 token 都被强化，失败回合什么也不贡献。GRPO 减掉组均值，消掉题目难易的影响。只有比同题平均表现好的回合，才被强化。组内奖励全部相同时，优势全是 0，这一组没有学习信号。这叫退化组（degenerate group），直接跳过，compute_group_advantages 返回 None。本机算的示意例子：

mean = sum(rewards) / len(rewards)
print(mean, sorted({r - mean for r in rewards}))

这像按班级平均分发奖学金。考得比同班平均好才有奖。一个班全满分或全零分，就没法比，这个班这次不评。

异步训练时，一组数据可能是几次更新以前的旧策略 πold 采的。对每个采样 token，重要性比是：

ρj = exp( log πθ(tj+1 | t≤j) − log πold(tj+1 | t≤j) )

框架支持三种 token 级损失。配置里 train.algo 选优势规则，train.loss_fn 另外选损失：

ppo：−Σj: mj = 1 min( ρjAj, clip(ρj, 1 − ε, 1 + ε) Aj )裁剪后的替代目标。GRPO 的几个训练都用它

importance_sampling：−Σj: mj = 1 ρjAj同上，但不裁剪。REINFORCE 那次训练用它

cross_entropy：−Σj: mj = 1 Aj log πθ(tj+1 | t≤j)按优势加权的对数似然。完全不管比率，只用在 Part 4.3"不修正"的消融里

logp_new, logp_old, A, eps = -0.9, -1.2, 0.625, 0.2  # 一个采样 token（示意的数）
rho = math.exp(logp_new - logp_old)
clipped = min(max(rho, 1 - eps), 1 + eps)
print(round(rho, 4), round(min(rho * A, clipped * A), 4))
# 输出: 1.3499 0.75
# ppo 取两者里小的，比率再大也只按 1.2 算。importance_sampling 不裁剪，就是 0.8437

def compute_group_advantages(
    rewards: Sequence[float],
    method: str = "grpo",
) -> list[float] | None:
    """Compute per-trajectory advantages for a group of rollouts of one task.

    Contract:
      - method="reinforce": each trajectory's advantage is its raw episode
        reward, no baseline. (Used with group size 1.)
      - method="grpo": group-relative advantages, each trajectory's reward
        minus the mean reward of its group. Requires a group of at least 2
        (raise ValueError otherwise). If every reward in the group is

8. 异步训练靠有界队列，学习者取组时判过期

异步训练让采样和更新同时进行，代价是数据可能过期。这一节依据 ASSIGNMENT.md Part 3 和 train/async_grpo.py。Part 3 占 25 分。

同步训练在采样时，学习者闲着。更新时，采样的 worker 闲着。异步训练把两者重叠起来。多个 rollout worker 一直用最新发布的策略生成组，放进一个有界队列。学习者从队列取组、训练、发布新版本。代价是，一组数据可能是几个版本前的策略采的。这叫"过期"（staleness）。超过 train.max_staleness 个版本的组直接丢掉，剩下的靠重要性权重修正。

这像食堂窗口。厨师不停往保温台上放菜，台子只放得下 16 盘，满了厨师就等。学生取菜时先看出锅时间，放太久的倒掉。

为什么 p3 会丢组？p5 配置的注释给了一个式子：(num_workers + queue_capacity) / groups_per_batch。它是一个慢学习者最终训练到的组，最多能旧几个版本。本机按这个式子算了四个异步配置。p3、两个 p43、p5 都是 (8 + 16) / 8 或 (32 + 16) / 16 = 3。p5 和 p43 的 max_staleness 是 4，比 3 大。p3 的 max_staleness 是 2，比 3 小，所以学习者跟不上时 p3 会丢组。上面的模拟正是这样。同样的耗时，max_staleness 2 时 6 步丢了 8 组，换成 4 一组不丢。这只是示意耗时下的结果。真实训练丢多少，看你自己的 summary/groups_dropped_stale。

9. 三个消融：组大小、同步对异步、要不要重要性加权

Part 4 在 Number Search 上做三个小研究，占 20 分。这一节依据 ASSIGNMENT.md Part 4 和 configs/。每个研究写一小节，带要求的图和一段分析，配置都原样用。

研究比较的训练只变了什么报告要点
4.1 组大小p2a（G = 1，REINFORCE）、p41（G = 2，GRPO）、p2b（G = 8，GRPO）新跑的只有 p41：group_size 2，其余同 p2b用 eval/success_rate 和 train/frac_degenerate_groups 解释组小了的影响。看优势方差、每步有用的序列数。REINFORCE 的退化比例记 N/A，因为没有组基线，日志里的 0 没意义。p2a 的优势规则和损失也不同。所以这不是纯粹的组大小消融
4.2 同步 vs 异步p2b、p3不用新跑复用 Part 3 的耗时分析，加上各自最后的 eval/success_rate，小表即可。解释加速从哪来，用旧数据训练有没有损失样本质量。证据用重要性权重统计和 p3 的 summary/groups_dropped_stale
4.3 高过期下的重要性加权p43_…_stale4_iw、p43_…_stale4_noiw都是异步、max_staleness 4，只差损失：ppo 对 cross_entropy两次训练的标准诊断图

4.3 的两次训练只差在损失上。iw 用 ppo，也就是带裁剪的重要性比。noiw 用 cross_entropy，按优势加权的对数似然，完全不管比率。比的就是高过期下，不做重要性修正会怎样。

组越小，退化组越多。做个示意的简化：同一题的每次采样独立，成功率都是 p。一组全对或全错的概率是 pG + (1 − p)G。本机算的：p = 0.5 时，G = 2 是 0.5000，G = 8 是 0.0078。p = 0.2 或 0.8 时，G = 2 是 0.6800，G = 8 是 0.1678。所以 p41 的配置注释说，它"会有多得多的退化组"。每步真正能用来训练的序列也更少。

p_degenerate = lambda p, G: p ** G + (1 - p) ** G  # 一组全对或全错的概率（示意的简化）
cases = [(p, G) for p in (0.5, 0.2) for G in (2, 8)]
print([round(p_degenerate(p, G), 4) for p, G in cases])
# 输出: [0.5, 0.0078, 0.68, 0.1678]
# G = 2 时一半甚至更多的组没有学习信号

掩码和错一位。掩码包含了观察 token，模型就在学预测环境。补全放在 L : L+c，而不是 L-1 : L-1+c，对数概率就挂错 token。同步训练的 ρ 会偏离 1。

把退化组当零优势样本塞进批。GRPO 的退化组要返回 None 跳过，但它仍算进组数和 mean_reward。整批都退化时，这一步就跳过。不更新、不存快照、不发布，但仍要记录一次。

先等 forward_backward，再提交 optim_step。这样每步延迟约翻倍。两个都提交后再等结果。也不要吞掉 SDK 的错误。

版本号和策略分开取。worker 应在生成开始时，一次性捕获 (policy, version)。等 await 回来再读版本，读到的可能已经是新版本。这时组上的版本和真正采样的策略对不上，过期判断全错。

轮询队列，或者让失败挂住训练。背压靠 await put/get。评测作为后台任务跑。任何失败都要取消其余任务，并抛出原来的异常对象。
